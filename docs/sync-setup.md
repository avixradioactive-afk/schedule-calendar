# 云同步 · 一步步配置

配置好之后：**手机和电脑看到的是同一份日程**。手机上出门记的东西，回家打开电脑就在了。
断网照常能用，联网了自动对上。

要把数据存在哪里由你决定——用你自己的一个 GitHub 私有仓库，不经过任何第三方服务。

总共三步，只做一次。第二台设备只要重复第三步。

---

## 第一步：建一个私有仓库（用来放数据）

1. 打开 <https://github.com/new>
   （或者点右上角的 **`+`** → **New repository**）

2. **Repository name** 填：

   ```
   schedule-data
   ```

   > 名字要和后面填的一致。你也可以叫别的，但要记住。

3. 下面选 **Private**（🔒 私有）

   > ⚠️ **别选 Public**。这是放你日程的地方，选公开等于所有人都能看到。

4. 勾上 **Add a README file**

   > ⚠️ **这一步别跳过**。GitHub 上「一个提交都没有的空仓库」是不让程序直接写文件的，
   > 勾了 README 就会自动产生第一次提交，就不会卡住。
   > 万一忘了勾，同步时应用会明确提示你去补一个。

5. 点 **Create repository**，完成。

---

## 第二步：建一个只授权这一个仓库的 Token

Token 相当于一把**只开这一个仓库的钥匙**，比密码安全，而且随时能吊销。

1. 点右上角**头像** → **Settings**

2. 左侧栏拉到**最底下** → **Developer settings**

3. 左侧栏 → **Personal access tokens** → **Fine-grained tokens**

4. 点 **Generate new token**

5. 按下面填：

   | 项目 | 填什么 |
   | --- | --- |
   | **Token name** | `schedule-sync` |
   | **Expiration** | `1 year`（最长。到期后同步会停下来并提示你换一个） |
   | **Resource owner** | 你自己的账号 |
   | **Repository access** | 选 **Only select repositories** → 只勾 `schedule-data` |
   | **Permissions** | 展开 **Repository permissions** → 找到 **Contents** → 改成 **Read and write** |

   > ⚠️ 两处别弄错：
   > - **Repository access 只勾 `schedule-data`**，不要选 All repositories。
   > - **只改 Contents 这一项**，别去动别的权限。
   >
   > 另外**千万不要**把这个 token 授权给 `schedule-calendar`（装网页代码的那个仓库）——
   > token 就存在那个页面里，等于把改代码的权限交出去了。

6. 点 **Generate token**

7. **立刻复制那串 `github_pat_...`**

   > ⚠️ **它只显示这一次**。关掉页面就再也看不到了，只能删掉重建一个。
   > 可以先粘到记事本，等下要用。

---

## 第三步：填进应用

1. 打开应用，点顶栏右边的 **`⋯`**

2. 点 **云同步**

3. **仓库**填 `你的用户名/schedule-data`
   （用户名就是 GitHub 网址里那个，比如 `avixradioactive-afk/schedule-data`）

4. **Token** 粘贴刚才那串

5. 点 **保存并同步**

   等一两秒，状态那行会变成「已同步到云端」。这时候去 GitHub 仓库页面刷新一下，
   能看到多了一个 `schedule.json`，里面就是你的数据。

6. 可以点 **测试连接** 单独确认仓库和 token 没问题。

**每台设备各填一次**（token 只存在那台设备本地，不会跟着数据跑到云端去）。

---

## 日常是什么样

配置好之后就不用管了。应用会自己：

| 什么时候 | 做什么 |
| --- | --- |
| 打开页面 | 拉一次，看云端有没有新东西 |
| 改了东西、停手约 20 秒 | 推上去 |
| 页面开着的时候 | 每 5 分钟看一眼云端 |
| 从后台切回前台 | 先把手头的改动送出去，再拉一次 |
| 断网 | 照常记在本地，联网了自动补上 |

如果两台设备**同时**都改了，应用不会偷偷替你选，而是弹出来让你看着办：

- **都保留（推荐）** —— 用云端的，同时把本机那份自动备份下来，一份都不丢
- **用云端的** —— 放弃本机这份（放弃之前也会自动备份）
- **用本机的** —— 用本机这份盖掉云端（同样先备份）

## 出问题怎么办

应用里会显示具体原因，对着看：

| 提示 | 意思 | 怎么办 |
| --- | --- | --- |
| `Token 无效或已过期` | 钥匙过期了或被吊销了 | 重新生成一个（第二步），填进去 |
| `Token 权限不够` | Contents 没给 Read and write | 回去改权限，或重新建一个 |
| `找不到仓库或文件` | 仓库名写错了，**或者 token 没授权到这个仓库** | GitHub 对「私有仓库没授权」也返回 404，所以两种都要查 |
| `仓库还没有任何提交` | 建仓库时没勾 README | 去仓库点 Add file → Create new file，名字填 `README.md`，提交一次 |
| `云端那份是空的，本地却有数据` | 云端文件被清空/清坏了 | 应用**没有**覆盖你的本地数据。去仓库的历史记录（History）看看 |
| `云端文件不是合法的 JSON` | 有人手改坏了 | 同上，从历史记录里翻回上一版 |
| `云端数据是更新版本的新版本` | 另一台设备用了更新的版本 | 先更新（手机上的 APK 要重装），再同步 |
| `GitHub 接口调用次数超了` | 极少见 | 等一会儿，会自动重试 |

**数据在哪儿？** 云端是 git 仓库，所以**每一次同步都是一个提交**。
万一真的搞坏了，去仓库的 **History** 里能找到之前任何一版，把内容复制出来就行。

## 几个你可能会担心的点

**要一直开着电脑吗？**
不用。数据存在 GitHub 的服务器上，那是他们的服务。你这边不用挂着任何东西，
也不用开着 GitHub 网页，也不用一直联网。

**要花钱吗？**
不用。私有仓库和这个用量的 API 调用都在免费额度里。

**Token 会泄露吗？**
- 它只存在你自己这台设备的浏览器里，**不会**被写进导出的 JSON 文件，也不会上传到云端。
- 只授权了 `schedule-data` 这一个仓库、只有 Contents 读写——就算泄露，也动不了你的其他仓库。
- 在公共电脑上用过的话，记得在应用里点「断开同步」，并去 GitHub 把那个 token 删掉。

**手机上的 APK 和手机浏览器，算两台设备吗？**
算。它们的存储是分开的，各自填一次 token 就行——但**填同一个仓库**，
这样它们和电脑就都通着。
